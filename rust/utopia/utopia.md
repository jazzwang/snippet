# Utopia 技術摘要

## 專案概述

Utopia 是由 DeepLethe 開發的企業級知識工程平台，是一個開源的知識工程基礎設施，能夠被動學習並自我治理。與傳統知識圖譜或向量存儲僅記錄當前知識不同，Utopia 將時態意識和本體（ontology）置於底層，讓知識系統隨資料到達而演進，並基於本體進行衝突檢測、推理和決策制定。該系統可離線部署，使企業能在自有硬體上建立知識基礎設施、可信任決策核心，並保留合規審計軌跡。

## 核心理念

Utopia 的名稱帶有某種浪漫色彩。托勒密的地心說曾被長期視為真理，直到哥白尼、開普勒、伽利略和牛頓逐步推翻它。回望歷史，我們保留的不僅是日心說正確這一事實，更是這一分步演進的過程。

當現有向量存儲和知識圖譜致力於正確呈現當前知識時，Utopia 的建設計劃之一是記錄理解變化的完整過程。工程實現後，這成為**雙時態知識圖譜**。當之後審查決策時，系統能產生它所採取的完整過程和所依據的理由。

## 架構特色

### 技術架構

- **最小化部署**：單一 Rust 二進制文件 + 一個 PostgreSQL 實例
- **內嵌功能**：全文檢索內嵌於二進制中，向量數據存入 pgvector，工作隊列直接放在表中
- **輕量化**：無需額外依賴服務

### 主要功能

| 功能 | 說明 |
|------|------|
| **知識導入** | 支援上傳 PDF、DOCX、PPTX、XLSX、ODS、CSV、TSV、Markdown、HTML 或純文本，自動檢測舊版編碼；網頁、RSS、GitHub、Jira、Notion、WebDAV 和 S3 相容儲存桶可設定排程同步；其餘資料透過 API 輸入 |
| **搜索與對話** | 基於 Tantivy 的全文檢索、pgvector 的向量搜索，結合 RRF 融合。答案流式輸出，內嵌引用可開啟來源段落。支援任何 OpenAI 相容介面（DeepSeek、Qwen、GLM、Ollama、vLLM），整個系統可離線運行 |
| **代理框架與代理 RAG** | 整個系統可透過對話驅動。內建代理搜尋文件、遍歷圖譜（實體在任一日期的事實或特定期間的變化）並查詢掛載的資料庫。相同只讀工具透過 MCP 暴露 |
| **本體與冷啟動** | 新建知識庫本身沒有詞彙；它從創建時選擇的套件開始。二進制內包含五個套件：schema.org、W3C Org、PROV-O、FOAF 和 IOF Core（可提出行業需求）；套件外的術語會根據出現情況計算；確認常見術語後它們加入本體 |
| **雙時態圖譜** | 提取將文件轉化為實體和事實，遵循可編輯的本體。每個事實都攜帶其所持時間和來源。更正事實時會封裝舊版本並連結新版本到它而非覆蓋，因此圖譜保留兩個時間軸：世界中的真實時間和系統相信它的時間 |
| **實體解析與審查** | 重複項在三個階段解決：精確名稱或別名、嵌入相似性，然後由模型對可疑配對做出判斷。每次合併都可逆。不確定情況進入審查隊列：低信心提取、疑似重複和基数衝突 |
| **推理與衍生** | 本體公理編譯為規則：傳遞性、對稱性、反函數和關係層次透過前向鏈結衍生新事實。衍生預設關閉，因為錯誤公理會衍生錯誤事實。衍生事實會標記為衍生，像任何其他事實一樣攜帶有效性和信心，並顯示它從何衍生。當它與斷言事實矛盾時，斷言的事實為準 |
| **衝突檢測** | 三類衝突，三組選擇。與舊事實衝突的新事實：封裝舊的、保留兩者或拒絕新的。違反公理（自迴路、不對稱、傳遞循環、基数）的資料：撤回事實、放鬆公理或接受兩者。首先檢查本體本身，因為自相矛盾本體的違反是雜訊 |
| **本體驅動查詢** | 將資料庫掛載在基礎（PostgreSQL、MySQL 及其協議引擎、透過 Trino 的 Iceberg/Delta Lake/Hive、Databricks、Snowflake），對話可對文件和資料庫進行查詢。代理建議其表如何映射到本體，由您確認。其背後的方法 [Ontology2SQL](https://github.com/deeplethe/ontology2sql) 在 SQLite 和 PostgreSQL 的 BIRD Mini-Dev 上達到最優狀態 |
| **多用戶與權限** | 每個知識庫有自己的成員和角色：擁有者、管理員、編輯者和查看者。開放基礎設施可由部署中所有人讀取，限制基礎設施僅透過邀請。第一個註冊的帳戶成為系統管理員 |
| **決策賬本** | 確認或拒絕事實、合併或還原實體、重建圖譜：每次都會留下記錄，說明誰、何時、對象當時是什麼樣子。賬本是追加式的，記錄會超越其對象甚至它屬於的基礎設施 |
| **決策智慧（開發中）** | 記錄決策、重現理解內容和決策過程，以及對疊加情境進行推理 |

## 快速開始

### 需求

- Docker（本地開發還需 Rust 1.85+、Node 20+、pnpm）

### 使用預建映像啟動

```bash
git clone https://github.com/deeplethe/utopia.git
cd utopia
docker compose --profile app up -d
```

開啟 http://localhost:1516 並註冊。第一個帳戶自動成為管理員，同時創建可由所有人讀取的公共知識庫。在提取商業文件前，於 Administration → Models 配置模型端點（對話和嵌入）。

### 從原始碼編譯

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml --profile app up -d --build
```

### 本地開發

```bash
# 1. PostgreSQL 搭配 pgvector
docker compose up -d db

# 2. 後端於 :1516，啟動時運行 migrations
cargo run -p utopia-server

# 3. 前端於 :5173，將 /api 代理到後端
cd web && pnpm install && pnpm dev
```

## 開發路線圖

- [ ] **決策推理**：約束計算，以及事後重現決策過程
- [ ] **商業規則**：人們在實體屬性事實、閾值或類別集上撰寫的規則，將其分類為帶有規則和前提作為解釋的衍生事實
- [ ] **執行閘門**：根據本體規則和符號邏輯檢查代理調用
- [ ] **MaxCompute**：探索映射和 Ontology2SQL 跨越阿里巴巴雲 MaxCompute（透過 Trino 的 Iceberg/Delta Lake/Hive、Databricks 和 Snowflake 已在其中，等待對真實叢集運行）
- [ ] **更多來源**：ClickHouse 驅動器；Feishu 連接器
- [ ] **精確到時刻**：在年/月/日旁側的 `instant` 精度，用於攜帶真實時間戳的來源。今日連接器將其四捨五入到 UTC 日，這可能將事件跨過午夜移位一天
- [ ] **基於 MCP 的代理記憶體**：集話寫入、檢索端點和 MCP 伺服器
- [ ] **企業級**：OIDC SSO、備份和還原指令、100k 文件的基準測試

## 版本狀態

Utopia 仍處於 **v0.1**。資料庫圖譜在版本間演進，migrations 僅向前滾動，無回滾。在生產環境中使用 `UTOPIA_IMAGE` 固定特定版本，並在使用前備份資料庫和 `data` 目錄。

請在對公眾網路開放前閱讀 [SECURITY.md](SECURITY.md)。
