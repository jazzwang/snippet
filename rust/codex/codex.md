## OpenAI Codex Harness：模型之外，執行系統如何影響 AI Agent

### 從稅務試點看 Codex Harness 的作用

2 月 20 日，OpenAI 聯合創始人 Greg Brockman 分享了一套由 Codex 驅動的稅務系統：這套系統在試點中處理了約 **7000 份報稅表**，將稅務準備時間縮短了 **1/3**。

這項數據顯示，OpenAI 這次的重點不在於發表參數更驚人的新模型，而是開源了名為 **Codex Harness** 的執行系統。這表示 AI 產品的差異，不只來自模型本身。「模型」並不是決定 AI 產品優劣的唯一變數。在這類應用中，開發者還得處理工具呼叫、失敗恢復、狀態保存，以及模型與既有工作流程的銜接。

### 把模型和 Harness 想成發動機與駕駛系統

可以把 AI 模型想成發動機，把 **Codex Harness** 想成駕駛系統。模型負責推理，Harness 則負責安排工具、保存狀態、處理錯誤，讓任務能一步步完成。

在 AI Agent 架構中，Harness 主要處理幾項執行工作：

*   **決策時機判斷**：決定何時讀取本機檔案，何時搜尋外部資訊。
*   **工具調度與容錯**：呼叫外部工具（API），並在任務失敗後嘗試恢復。
*   **效能與上下文壓縮**：透過上下文壓縮，減少長對話造成的資訊遺失與額外運算。
*   **狀態維護與權限管理**：保存任務執行緒（Thread）與存取權限紀錄，再把工具結果回傳給模型，供模型決定下一步。

模型負責推理，Harness 負責把推理轉成工具呼叫與後續操作。

### 同一個模型，Harness 如何影響測試分數

這組數據顯示，系統組織方式也會明顯影響模型表現。在 ARC-AGI 公開測試集上，同一個 **GPT-5.6s** 模型在不同系統組織方式下，測試分數如下：

*   **使用基礎 Harness 執行**：得分僅為 13.3。
*   **開啟推理（Reasoning）狀態保留與上下文壓縮後**：得分升至 **38.3**。

同時，在表現提升近 3 倍的情況下，輸出的 **token 數量反而降至約原本的 1/3**。這表示 Harness 在減少重複處理的同時，保留了推理狀態與上下文。透過減少重複處理，Harness 讓模型用較少的 token 取得較高的測試分數。至少在這組測試中，系統組織方式對結果的影響不亞於模型本身。

### AI 可以直接嵌入既有工作介面

不少 AI 產品把聊天框當成預設介面，即使使用者原本是在告警、帳單或病例等專業系統中工作。但在某些專業工作中，聊天框未必是最合適的操作方式。工程師查看告警、財務人員處理帳單、醫師審閱病例時，不必為了使用 AI 而離開原本的專業介面。

比較理想的做法，是把 AI 放進專業人士原本使用的系統，讓它在既有流程中協助執行工作：

*   **Cisco 案例**：在 **Cisco Club Control** 平台中推出 **App Builder**，直接嵌入 Codex SDK，讓使用者能以自然語言在原有平台上建立客製化應用，不必切換到其他介面。
*   **VE Holdings and Cate 案例**：在稅務處理中，AI 直接嵌入報稅流程，不以聊天機器人的介面呈現。會計師仍負責必要的修改與審核，系統則把這些操作轉成評測訊號，用來改進後續表現。

### 開發者的三條路：Codex Harness 的技術演進

Codex 的整合方式不只限於獨立產品。對開發者來說，專業領域資料、工作流程與介面的整合方式，會直接影響產品能否落地。

| 整合方式 | 推出時間／進度 | 適用場景 | 核心技術特性 |
| :--- | :--- | :--- | :--- |
| **Codex Extract** | 基礎能力 | 腳本撰寫、CI 流程 | 處理邊界清晰、任務單一的自動化工作流程。 |
| **Codex SDK** | 2025 年推出 | 業務邏輯嵌入 | 可建立可恢復的執行緒、執行複雜任務，並接收結構化輸出。 |
| **Codex App Server** | 2026 年 2 月 | 深度整合產品介面 | 透過 **JSON-RPC 介面**，把 Agent 迴圈接到既有 UI，讓使用者保留原本的操作方式。 |

### 企業級應用的安全與權限

需要注意的是，OpenAI 開源的是 **Harness 的程式碼（基於 Apache 2.0 授權條款）**，不是模型權重或算力。因此，採用開源 Harness 不會讓推理成本歸零，企業仍需維持安全控管。

企業部署 Agent 時，至少要處理以下三項安全問題：
1.  **權限邊界與沙箱審計**：嚴格限制 Agent 存取內部資料庫與敏感檔案的權限。
2.  **工具白名單**：定義 Agent 可呼叫的 API 範圍。
3.  **人機協作（Human-in-the-loop）**：高風險動作（如資金轉帳、程式碼發布）必須由人員最後確認。

### AI 會如何進入既有軟體

模型影響推理能力的上限，Harness 則影響這些能力能否轉成實際操作。

未來的 AI 產品不一定會把聊天框放在操作核心。這類產品可能不需要巨大的輸入框或機器人頭像，也不必要求使用者重新學習原有操作方式。

使用者仍在熟悉的開發環境或財務系統中工作，系統則能理解任務、執行操作並呼叫工具。軟體可以在背景處理部分繁瑣工作，並在需要人工決策時請使用者確認。重點不是讓 AI 另開一個聊天介面，而是讓它在既有系統中完成可授權的工作，並在必要時交由人員確認。
