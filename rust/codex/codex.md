## OpenAI Codex Harness：模型只是發動機，這套「駕駛系統」才是顛覆 AI Agent 開發的關鍵

### 引言：OpenAI 的反直覺策略

2 月 20 日，OpenAI 聯合創始人 Greg Brockman 分享了一個令產業界深思的反直覺案例：一套由 Codex 驅動的稅務系統在試點中處理了約 **7000 份報稅表**，並成功將稅務準備時間縮短了 **1/3**。

然而，身為技術分析師，我們必須洞察這項數據背後的深層意義：OpenAI 這次的重點不在於發表參數更驚人的新模型，而是開源了名為 **Codex Harness** 的執行系統。這標誌著一個重大的技術典範轉移（Paradigm Shift）——大模型的參數競賽已進入平穩期，「模型」本身不再是決定 AI 產品優劣的唯一變數。當前 AI Agent 開發的真正瓶頸，在於如何讓模型與現實世界的複雜工作流精準對接。

### 核心隱喻：發動機 vs. 駕駛控制系統

若將 AI 模型比作一台馬力強勁的「發動機」，那麼 **Codex Harness** 就是負責將動力轉化為位移的「駕駛控制系統」。發動機負責燃燒數據並輸出推理，但要讓一輛車安全、精準地到達目的地，還需要變速箱、方向盤、導航與剎車。

在 AI Agent 的架構中，Harness 承擔了原本被開發者忽視的底層職能：

*   **決策時機判斷**：決定何時該讀取本地文件，何時該發動外部資訊搜索。
*   **工具調度與容錯**：精準呼叫外部工具（API），並在任務失敗後啟動恢復機制。
*   **效能與上下文壓縮**：透過「上下文壓縮」（Context Compression）技術，解決長對話導致的遺忘與運算資源浪費。
*   **狀態維護與權限管理**：保存任務現程（Thread）、處理存取權限記錄，並將工具執行結果回傳給模型，以決定下一個行動。

簡而言之：**模型負責「思考」，而 Harness 負責讓思考「落實於現實世界」。**

### 數據說話：不換模型也能提升 3 倍表現？

OpenAI 揭露的數據徹底打破了「模型越強，產品越強」的迷思。在 ARC-AGI 公開測試集上，同一個 **GPT-5.6s** 模型，其表現隨系統組織方式的不同而產生劇烈變革：

*   **使用基礎 Harness 運行**：得分僅為 13.3。
*   **開啟推理（Reasoning）狀態保留與上下文壓縮後**：得分飆升至 **38.3**。

更驚人的事實是，在表現提升近 3 倍的同時，其輸出的 **token 數量反而降至約原本的 1/3**。這背後的關鍵技術在於「最大限度地發揮智力，同時極小化無謂的浪費」。透過消除冗餘的重複處理，Harness 讓模型在更精簡的運算下達成更高質量的決策。這證明了大模型的競爭重點已從單純的「參數規模」轉向了**系統組織能力**。

### 告別「對話框迷思」：AI 應是隱形的執行力

過去三年，AI 產品開發陷入了一種「對話框迷思」（Chatbox-first UI）的誤區：無論是什麼軟體，都盲目地強加一個聊天框。然而，對話框只是 UX 演進過程中的臨時支撐。工程師查看告警、財務人員處理賬單、醫生審閱病例，這些專業工作都不應該為了使用 AI 而離開他們深耕多年的專業介面。

專業人士不應被迫去適應 AI 介面，而是應讓 AI 進入人原本就在使用的環境。這正是「隱形執行力」的願景：

*   **Cisco 案例**：在 **Cisco Club Control** 平台中推出 **App Builder**，直接嵌入 Codex SDK，讓用戶能以自然語言在原有平台上創建定制化應用，無需跳轉。
*   **VE Holdings and Cate 案例**：在稅務處理中，AI 並非以「聊天機器人」的形式出現，而是靜默地嵌入報稅流程。會計師只需進行關鍵的修改與審核，而這些行為會轉化為評測信號，反哺系統改進。

### 開發者的三條路：Codex Harness 的技術演進

Codex 正在從一個獨立產品轉向一種基礎能力。隨著技術成熟，開發者擁有的「護城河」將重新回到對專業領域數據、工作流與介面的掌握。以下是 Codex Harness 提供的三種技術路徑：

| 整合方式 | 推出時間/進度 | 適用場景 | 核心技術特性 |
| :--- | :--- | :--- | :--- |
| **Codex Extract** | 基礎能力 | 腳本編寫、CI 程序 | 處理邊界清晰、任務單一的自動化工作流。 |
| **Codex SDK** | 2025 年發布 | 業務邏輯嵌入 | 可創建恢復線程、運行複雜任務、接收結構化輸出。 |
| **Codex App Server** | 2026 年 2 月 | 產品界面深度整合 | 透過 **JSON-RPC 接口**將 Agent 循環接入原有 UI，保留專業操作習慣。 |

### 企業級應用的防線：安全與權限

分析師必須提醒企業：OpenAI 開源的是 **Harness 的程式碼（基於 Apache 2.0 協議）**，而非模型的權重或算力。這意味著擁抱開源 Harness 並不代表推理成本歸零，更不代表可以放棄安全邊界。

成熟的企業級 Agent 必須建立以下防線：
1.  **權限邊界與沙箱審計**：嚴格限制 Agent 存取內部數據庫與敏感文件的權限。
2.  **工具白名單**：定義 Agent 獲准調用的 API 範圍。
3.  **人機協同 (Human-in-the-loop)**：高風險動作（如資金轉賬、代碼發布）必須由人類最終確認。

### 結論：未來軟體的模樣

**模型決定了智能的上限，而 Harness 決定了智能能否真正幹活。**

當前「對話框優先」的 UI 時代即將劃上句點。未來最強大的 AI 產品將會顯得格外「安靜」——它沒有巨大的輸入框，沒有閃爍的機器人頭像，也不會要求你重新學習操作方式。

你打開的依然是熟悉的開發環境或財務系統，只是它開始具備了自我理解、自我執行與調用工具的能力。軟體將會靜默地執行大部分繁瑣工作，只在真正需要決策的關鍵時刻停下來詢問用戶：「這一步要執行嗎？」這種「不干擾、只執行」的形態，才是 AI 真正進入現實世界生產力的模樣。
