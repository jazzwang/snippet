# Grafana k6 負載測試技術報告

## 簡介

k6 是由 Grafana Labs 開源的現代化負載測試工具，專為開發人員和測試人員在 DevOps 時代進行效能測試而設計。k6 的核心設計目標是提供最佳的開發者體驗，其特點包括：

- **可配置的負載產生**：即使是低階機器也能模擬大量流量
- **測試即代碼（Tests as Code）**：可重用腳本、模組化邏輯、版本控制，並與 CI 整合
- **完整的 API**：腳本 API 包含豐富的功能，可模擬真實應用程式流量
- **內嵌 JavaScript 引擎**：結合 Go 的效能和 JavaScript 的腳本熟悉度
- **多協議支援**：支援 HTTP、WebSockets、gRPC、Browser 等多種協議
- **大型外掛生態系**：可擴展 k6 以支援您的需求
- **靈活的指標儲存和可視化**：可匯出到您選擇的服務

## 系統需求

k6 可在以下環境上運行：

| 平台 | 要求 |
|------|------|
| **macOS** | macOS 10.15+，支援 Apple Silicon、Intel |
| **Windows** | Windows 10/11，推薦使用 WSL 2 |
| **Linux** | Debian/Ubuntu 20.04+，支援 x86_64、ARM64 |
| **Docker** | Docker 19.03+ |

**前置需求：**

- 基本的 JavaScript 或 TypeScript 知識
- 程式碼編輯器（如 Visual Studio Code、JetBrains 編輯器）
- Go 1.21+（如需自行編譯）
- Node.js 18+（如使用某些外掛）

### 方法一：使用包管理器（推薦）

```bash
# 驗證安裝

```

#### Linux（Debian/Ubuntu）

```bash

curl -fsSL https://dl.k6.io/key.gpg | sudo gpg --dearmor -o /usr/share/keyrings/k6-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" | sudo tee /etc/apt/sources.list.d/k6.list

sudo apt-get install k6

# 方法 B：簡化版
sudo gpg -k
sudo gpg --no-default-keyring --keyring /usr/share/keyrings/k6-archive-keyring.gpg --keyserver hkp://keyserver.ubuntu.com:80 --recv-keys C5AD17C747E3415A3642D57D77C6C491D6AC1D69
echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" | sudo tee /etc/apt/sources.list.d/k6.list
sudo apt-get update
sudo apt-get install k6
```

## 測試步驟

### 1. 建立測試腳本

建立一個基本的負載測試腳本：

```javascript
// 基本測試腳本：basic-test.js
import http from "k6/http";
import { check, sleep } from "k6";

// 測試配置
export const options = {
  // 設定閾值（Thresholds）
  thresholds: {
    // 斷言 99% 的請求在 3000ms 內完成
    http_req_duration: ["p(99) < 3000"],
    // 請求失敗率不超過 1%
    http_req_failed: ["rate < 0.01"],
  },
  // 設定虛擬用戶（VUs）的 ramp-up 階段
  stages: [
    // 30 秒內從 0 增加到 15 個 VUs
    { duration: "30s", target: 15 },
    // 維持 15 個 VUs 持續 1 分鐘
    { duration: "1m", target: 15 },
    // 20 秒內從 15 個 VUs 減少到 0
    { duration: "20s", target: 0 },
  ],
};

// 模擬用戶行為
export default function () {
  // 發送 GET 請求
  let res = http.get("https://httpbin.org/get");
  
  // 驗證回應狀態碼
  check(res, {
    "status was 200": (r) => r.status === 200,
    "had JSON body": (r) => r.json !== null,
  });
  
  // 休眠 1 秒，模擬用戶等待
  sleep(1);
}
```

### 2. 執行測試

```bash
# 基本執行（執行一次）
k6 run basic-test.js

# 指定執行時間（30 秒）
k6 run --duration 30s basic-test.js

# 設定虛擬用戶數量（最大 20 個）
k6 run --vus 20 --iterations 100 basic-test.js

# 使用自定義配置檔案
k6 run --config critical-load.config.json basic-test.js
```

### 3. 進階測試範例

#### HTTP 測試（多階段）

```javascript
// 多階段 HTTP 測試
import http from "k6/http";
import { check, sleep } from "k6";

export const options = {
  stages: [
    { duration: "2m", target: 50 },
    { duration: "5m", target: 100 },
    { duration: "5m", target: 50 },
    { duration: "2m", target: 0 },
  ],
};

export default function () {
  const res = http.get("https://httpbin.org/delay/1");
  
  check(res, {
    "status is 200": (r) => r.status === 200,
    "response time < 5s": (r) => r.timings.duration < 5000,
  });
  
  sleep(0.5);
}
```

#### 使用自定義指標

```javascript
// 自定義指標範例
import http from "k6/http";
import { Counter, Rate } from "k6/metrics";

// 定義自定義指標
const customErrors = new Counter("custom_errors");
const successfulRequests = new Counter("successful_requests");
const requestSuccessRate = new Rate("request_success_rate");

export const options = {
  thresholds: {
    custom_errors: ["count < 5"],
    successful_requests: ["count > 100"],
    request_success_rate: ["rate > 0.95"],
  },
};

export default function () {
  const res = http.get("https://httpbin.org/get");
  
  if (res.status === 200) {
    successfulRequests.add(1);
    requestSuccessRate.add(true);
  } else {
    customErrors.add(1);
  }
}
```

#### 使用 k6 外掛

```javascript
// 使用 Chrome 瀏覽器測試（需安裝 chromium 外掛）
import { chromium } from "k6/x/chromium";

export const options = {
  stages: [
    { duration: "1m", target: 5 },
    { duration: "1m", target: 0 },
  ],
};

export default async function () {
  const browser = await chromium.launch();
  const page = await browser.newPage();
  
  await page.goto("https://example.com");
  const title = await page.title();
  
  console.log(`Page title: ${title}`);
  
  await browser.close();
}
```

## 驗證步驟

### 1. 驗證測試結果

執行測試後，檢查輸出是否包含：

```bash
# 查看完整輸出
k6 run script.js 2>&1 | tee test-output.txt

# 查看摘要報告
k6 run --summary-export=summary.json script.js
```

**驗證項目：**

- [ ] 所有測試階段已正確執行
- [ ] 虛擬用戶數量符合預期
- [ ] 閾值（thresholds）已正確設定
- [ ] 輸出指標包含 `http_req_duration`、`http_req_failed` 等
- [ ] 測試結果已匯出到指定檔案

```bash
# 語法檢查（k6 0.43+）
```

### 3. 驗證整合測試（CI/CD）

#### GitHub Actions 範例

```yaml
# .github/workflows/k6-test.yml
name: k6 Performance Tests

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  performance-test:
    runs-on: ubuntu-latest
    
    steps:
      - name: Checkout code
        uses: actions/checkout@v4
      
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
      
      - name: Install dependencies
        run: npm ci
      
      - name: Run k6 tests
        uses: grafana/k6-action@v4
        with:
          # 可選：使用 k6 Cloud
          # cloud: ${{ secrets.K6_CLOUD_TOKEN }}
          # 自定義設定
          arguments: --summary-export=summary.json --out json=results.json
          # 測試腳本
          script: 'scripts/performance-test.js'
      
      - name: Upload results
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: k6-results
          path: |
            results.json
            summary.json
```

## 最佳實踐

### 1. 腳本組織

```
project/
├── scripts/
│   ├── basic-test.js
│   ├── load-test.js
│   └── e2e-test.js
├── config/
│   ├── thresholds.json
│   └── stages.json
├── reports/
│   ├── summary.json
│   └── results.csv
└── .k6/
    └── config.yml
```

### 2. 安全最佳實踐

- 避免在腳本中硬編碼憑證
- 使用環境變數儲存敏感資訊
```javascript
const apiKey = process.env.API_KEY;
const httpParams = { headers: { Authorization: `Bearer ${apiKey}` } };
```

### 3. 效能最佳化

- 使用 `check` 而非 `if` 進行驗證
- 避免在 `default` 函數中進行耗時操作
- 使用 `afterScenario` 清理資源
```javascript
export function afterScenario() {
  // 清理操作
}
```
