隨著 Qwen 3.5 等強大開源模型的崛起，本地端運行 AI 的門檻正變得越來越高，其中最讓開發者感到挫折的莫過於「VRAM 焦慮」。要流暢運行這些參數龐大的模型，顯示記憶體（VRAM）的需求簡直是無底洞。在動輒花費數千美金追求 RTX 5090 之前，我們需要一種更聰明的硬體策略。

如果你正苦於 8GB 或 12GB VRAM 的束縛，又不願支付昂貴的「Nvidia 稅」，現在有一條極具技術性價比的路徑：僅需約 200 美金的二手 Intel Arc A770 16GB。這張曾經被視為遊戲市場邊緣人的顯卡，正憑藉著其優異的記憶體配置，成為打破算力壟斷的關鍵武器。

根據實測，在運行 Qwen3 14B 模型（Q4KM 量化）時，透過常用的 Vulkan 框架速度約為 25 t/s。然而，若切換至 Intel 自家的 **OpenVINO** 框架，推論速度可提升至近 **30 t/s**。這背後的技術關鍵在於 OpenVINO 能有效調用 A770 內建的 **XMX (Matrix Multiplication Units)** 矩陣計算單元，這是目前 Vulkan 或 llama.cpp 尚未完全優化利用的部分。

##### 關鍵技術發現：MOE 模型的神速效率

硬體只是基礎，模型架構的選擇（Model Architecture Selection）則是發揮效能的靈魂。Qwen 3.5 35B 採用的 **混合專家模型（MOE）** 架構，在 Intel A770 上展現了驚人的吞吐量。

MOE 架構的優點在於「條件式激活」：處理任務時僅啟動相關的專家層。數據對比顯示，RX 6800 在運行 14B Dense 模型時速度為 40 t/s（接近其 57 t/s 的記憶體頻寬理論極限），但在運行容量更大的 35B MOE 模型（IQ2_M 量化）時，速度竟然翻倍達到 **75 t/s**。在 A770 上，MOE 同樣能維持約 **50 t/s** 的高速，這證明了 MOE 是目前提升硬體單位效能的最優解。

##### 避坑指南：混合 GPU 設置的四大注意事項

要穩定運行這種非典型的雙卡設置，必須在物理與軟體層面進行精細微調：

###### H4: 物理空間與散熱管理 (Physical Clearance & Thermal Management)
當雙卡併行時，兩張卡之間往往僅剩 3-4mm 的間隙。為了防止顯卡因進氣不足產生 **熱切點（Thermal Throttling）**，必須手動增加機殼風扇強制對流，確保副卡在長時間推論下仍能維持穩定的時脈。

###### H4: BIOS 關鍵配置
這是發揮 Intel Arc 效能的前提。你必須在 BIOS 中同步開啟 **Above 4G decoding** 與 **Resizable Bar (Re-Size BAR)**。忽略此步驟將導致 Arc 顯卡在數據傳輸上產生巨大瓶頸。

###### H4: 軟體版本與 Flash Attention 兼容性
在使用 **LM Studio 0.4.9** 搭配當前 Intel 驅動時，請務必 **關閉 Flash Attention**。實測發現，開啟此功能會導致 A770 在生成回應末尾出現亂碼。目前關閉此選項對推論速度並無顯著影響。

###### H4: Windows PCIe 電源管理
Windows 預設的「PCI Express 連結狀態電源管理」可能會在顯卡閒置時將其置於低功耗狀態。這會導致 LM Studio 誤判顯卡已斷開並解除載入。建議在電源選項中將其設定為「關閉」。

這裡需要注意一個技術細節：在混搭不同廠牌 GPU 時，LM Studio 預設使用 **「平均分配（Split Evenly）」** 策略。這意味著系統推論速度會被較慢的那張顯卡所限制。儘管 RX 6800 單獨運行 MOE 時極快，但在雙卡協同下，它會被限制在 A770 的速度水平，最終產出約 **50 t/s** 的成績。

然而，這已經足以在 28GB 的大型模型上提供極致流暢的體驗。以遠低於旗艦卡的預算，解決了「從不能跑到跑得飛快」的質變問題。

Intel Arc A770 的案例證明了：AI 算力不應只是預算競賽。透過對 PCIe 頻寬特性的理解、MOE 模型架構的選擇以及跨廠牌硬體的混搭，我們可以繞過昂貴的封閉生態系，實現算力自由。

### 比 Nvidia 便宜一半卻擁有 32GB VRAM？Intel Arc Pro B70 正在顛覆 Local AI 的遊戲規則

在 Local AI 的圈子裡，我們常戲稱這是一場「硬體成癮症」的蔓延。對於開發者與愛好者而言，追求在本地端流暢執行大型語言模型（LLM）的過程，本質上就是對顯存（VRAM）無止盡的渴求。然而，現實往往很骨感：為了填滿那幾十 GB 的 VRAM，你通常得在昂貴的旗艦卡與空空如也的錢包之間做抉擇。

長期以來，Nvidia 憑藉穩健的 CUDA 生態系壟斷了話語權，但其高昂的「入坑稅」讓許多人望而卻步。就在此時，Intel 帶著 Arc Pro B70 殺入戰局，開出了「32GB VRAM 且低於 1,000 美元」的震撼條件。這張卡究竟是能讓預算有限的玩家翻身的「神兵利器」，還只是另一個活在紙面數據上的實驗品？讓我們進入 2026 年的硬體戰場一探究竟。

#### 2. 震撼市場的價格破壞者：32GB VRAM 只要不到 1,000 美元

Intel Arc Pro B70 最核心的競爭力非常直白：它在價格與顯存容量之間劃出了一條全新的界線。在追求長文本處理（Long Context）與高併發任務的今天，32GB 的大容量 VRAM 意味著你能留出更充裕的 KV Cache 空間，這對於運行如 Qwen 34B 級別的模型至關重要。

以下是目前市場上幾款主流專業顯示卡的橫向對比：

#### 3. 效能逆襲：當「帳面數據」輸給了實際表現

身為資深評論家，我一向主張「實測大於規格」。在 Qwen 34B BF-16（無量化）的原生格式測試中，B70 展現了令人意外的「低規高跳」：

- **Prompt 處理速度：** B70 表現極其強悍，在特定測試中衝破 **14,000+** 關卡，而價格貴出一截的 RTX 4000 則維持在 12,000+。
- **多模態表現：** 在 LTX2 影片生成測試中，B70 僅用 **144 秒** 便完成了任務，對比 AMD R9700 的 169 秒，Intel 在處理複雜視覺模型上展現了約 15% 的領先優勢。

儘管 RTX 4000 擁有較高的記憶體頻寬，但 B70 在原生浮點運算上的優化顯然更到位。

> 「我發誓我不是在試圖讓 B70 看起來更好，但與這張 GPU [RTX 4000] 相比，它的效能稍微好一點，這是我沒想到的。」

#### 4. 軟體疊層：AMD 的「崎嶇之路」與 Intel 的專屬優化

硬體是軀幹，軟體則是靈魂。測試中，AMD R9700 儘管規格亮眼，但在實際運行中卻被 B70「摧毀」。這再次證明了**軟體疊層 (Software Stack)** 的重要性。

Intel 為了在 Local AI 市場插旗，投入了巨大資源優化其軟體生態：
- **IPEX (Intel Extension for PyTorch)：** 提供專屬的 PyTorch 加速支援。
- **VLM Omni：** 針對多模態模型（視覺 + 語言）進行大規模優化，讓 ComfyUI 等工具能流暢運行。
- **SYCL：** 跨架構的抽象層，讓開發者能更輕易地將 CUDA 程式碼遷移至 Intel XPU 架構。

相比之下，AMD 的 ROCm 雖然在追趕，但目前的轉譯效率（HIP/CUDA）仍不夠穩定。Intel 透過特定補丁與自有的編譯技術，已經在軟體成熟度上領先 AMD 一個身位。

#### 5. 量化技術的陷阱：AWQ 與算力分配的藝術

然而，Nvidia 依舊擁有其護城河。當我們進入 **AWQ (Activation Aware Quantization)** 模式（4-bit 量化）時，風向出現了逆轉。

AWQ 的精髓在於它不會粗暴地壓縮所有參數，而是先分析模型的「激活（Activations）」，保護重要的權重不被過度損耗。在 4-bit 環境下，Nvidia RTX 4000 憑藉深厚的架構優化，以 89 t/s 的 Token 生成速度反超了 B70 的 72 t/s。

**核心洞察：** 如果你的工作流依賴原生的 BF-16 精度，Intel 是極致性價比之王；但如果你傾向使用極度壓縮的 4-bit 模型來追求極致速度，Nvidia 的軟體優化仍具備優勢。

#### 6. 當四張 B70 聯手：128GB VRAM 的夢想與 PCIe 的現實壁壘

為了測試極限，我將四張 B70 塞進了同一台機器，獲得了驚人的 **128GB 總 VRAM**。這意味著你可以同時加載多個 30B-32B 規模的模型，並擁有極其龐大的上下文視窗（Context Window），這在處理「Vibe Coding」或使用 Abacus AI 的 Z agent 進行自動化編碼任務時，顯現出了無與倫比的吞吐優勢。

- **通訊瓶頸：** 雖然單卡支援 PCIe Gen 5，但 GPU 之間的點對點通訊被限制在 **63 GB/s**。
- **負面擴展：** 在小型模型的單次請求測試中，由於多顯卡間的通訊延遲，Token 生成速度反而會從 72 下降到 52。

但對於「Agentic Workflow（代理工作流）」來說，這套系統聽起來就像一場「機械交響樂」——或者說，聽起來像裡面養了一隻倉鼠。

#### 7. 聽覺上的驚喜：當 GPU 聽起來像「間諜電影」

這張卡有個非常有趣的特質：電感嘶鳴（Coil Whine）。在高併發處理數據時，B70 會發出一種有節奏的、類似電子脈衝的聲響。

> 「如果你的聽力非常敏銳，你就能精確地告訴我正在運行什麼模型、正在處理多少個併發請求。」

### Nvidia RTX Spark：是 AI 時代的革命，還是被浪費的硬體？

#### **引言：當 Jensen 的豪言壯語遇上網路負評**

在最近的 Keynote 演講中，Nvidia 執行長黃仁勳（Jensen Huang）以一貫的霸氣姿態宣告，RTX Spark 將「重新定義 PC」，並將其視為 40 年來運算架構的首度重塑。然而，這番宏大願景在技術社群中卻引發了兩極反應。

儘管硬體規格驚人，社群媒體上卻出現了不少「浪費資源」的聲音。許多開發者對於「首發僅支援 Windows」感到極度憤怒，甚至直言：「將 128GB 的統一記憶體浪費在 Windows 這種肥大的作業系統上，簡直是種罪過。」這不禁讓人產生疑問：這款硬體究竟是 Nvidia 佈局未來的神來之筆，還是另一場公關災難？為什麼這款硬體會讓市場產生如此強烈的愛恨情仇？

#### **觀點一：為什麼「Windows 優先」可能是 Nvidia 最聰明的棋局？**

面對 Linux 社群的怒火，身為分析師，我認為 Nvidia 選擇 Windows 作為首發點並非失策，而是看準了 ARM 生態系的「最後一哩路」。事實上，Linux on ARM 在伺服器與行動端早已是「已解決的問題」（Solved problem），但在個人運算領域，Windows 才是那個最難攻克的堡壘。

Microsoft 多年來試圖將 Windows 移植到 ARM 架構的過程，簡直就像是用「釘槍」（Staple gunning）把不同部件勉強湊合在一起，經歷過多次失敗與掙扎。但現在，隨著 Prism 模擬層的成熟，Nvidia 選擇在此刻切入，是為了直接在難度最高的主戰場建立灘頭堡。

另一個現實因素在於軟體供應商。創意工作者離不開的 Adobe 全家桶，即便早已針對 Qualcomm 晶片開發了 Windows on ARM 版本，至今仍拒絕登陸 Linux。因此，若要建立一個真正能與傳統 PC 競爭的生態系，攻下 Windows 是最快也最務實的路徑。

> 「Windows 其實是一個困難的案例，所以他們選擇從困難的問題入手。Linux on ARM 基本上已經在伺服器和手機領域被解決了。讓擁有 40 年應用程式遺產的 Windows 能在 ARM 上跑得順暢，才是真正的挑戰。」—— Alex Ziskind

#### **觀點二：RTX Spark 的真相——穿著新衣服的 DGX Spark？**

撕開行銷標籤後，身為硬體專家的我們可以清楚看到，RTX Spark 並非什麼橫空出世的新架構。這是一個高明的「晶片組技巧」（Chiplet trick）：Nvidia 將一個 Blackwell GPU 晶粒與 MediaTek 的 CPU 晶粒透過高速 NVLink 結合在一起。

這與先前針對高階開發者推出的 DGX Spark 硬體結構如出一轍。同樣的 20 核 ARM CPU 配置，雖然官方宣稱 GPU 效能接近 RTX 5070 Ti，但根據目前的技術評估與早期數據，我認為其實際表現可能更接近 AMD 的「Strix Halo」機器，而非獨立顯卡的 5070 Ti。這種「重新包裝」的策略，其實是將原本鎖定極少數開發者的技術，轉化為大眾消費品，這對推動 ARM PC 普及具有關鍵意義。

#### **觀點三：告別「電競磚頭」，AI 筆電的「統一記憶體」革命**

目前的頂級顯卡筆電（如搭載 RTX 5090 的機型）雖然效能強悍，但體積巨大且必須拖著一顆像「磚頭」一樣的變壓器。RTX Spark 的出現，象徵著效能與便攜性之間的平衡。

其功耗設計在 45W 至 80W 之間，這意味著它能裝入更輕薄的機身，甚至在電池供電下也能維持一定的續航。而最核心的「秘密武器」莫過於高達 128GB 的**統一記憶體（Unified Memory）**。這項技術打破了傳統 GPU 顯示記憶體（VRAM）的限制，讓 GPU 能直接存取整個系統 RAM。這與 Apple M 系列晶片的架構異曲同工，讓筆電能流暢運行那些原本需要數萬美金工作站才能跑動的大型語言模型（LLM）。

以下是 RTX Spark 鎖定的四類核心族群及其受益點：

*   **玩家**：終於能擁有兼具輕薄外型與高效能的裝置，擺脫笨重的散熱模組與變壓器。
*   **創意者**：128GB 記憶體能輕鬆應對 Adobe 套件極度耗費資源的 8K 影像剪輯，不再受限於 VRAM 溢位。
*   **開發者**：提供 16GB 到 128GB 的彈性配置，在本地端就能直接進行複雜的開發與模擬。
*   **AI 愛好者**：能在不依賴雲端的情況下，於筆電上本地運行大型 AI 模型。

#### **觀點四：價格迷霧與「晶片篩選」的成本策略**

DGX Spark 的起步價高達 4,700 美元，顯然不是給一般人買的。但 RTX Spark 預計會大幅調降價格。Nvidia 採用的核心手段是「晶片篩選」（Binning）技術：

根據晶片體質，會區分為 **N1X（滿血版 20 核）** 與 **N1（精簡版）**。那些在生產過程中略有瑕疵的晶片會被關閉部分核心，轉為 8 到 10 核的 N1 等級，並搭配 16GB 記憶體以低價搶市。此外，RTX Spark 移除了許多昂貴的企業級零件，例如原本在 DGX 機器內價值 1,500 美元的 Connect X7 高階網卡，在消費版中會被更實際的 10G 乙太網路取代，這將使價格大幅下修。

#### **觀點五：CUDA 護城河——Nvidia 無可取代的殺手鐧**

儘管 Qualcomm 的 Snapdragon X Elite 在電池續航上表現出色，但 Nvidia 手中握有的「CUDA 棧」（CUDA Stack）是其不可撼動的護城河。

對於 AI 開發者來說，工具鏈的相容性高於一切。即便開發者再怎麼偏愛 Linux 或抱怨 Windows，只要他們的工作流（Workflows）深深植根於 CUDA 之上，RTX Spark 就是市場上唯一具備便攜性與軟體相容性的選擇。這是 Nvidia 敢於挑戰 Qualcomm、甚至是挑戰 x86 傳統市場的底氣。

#### **結語：這會是 PC 的「智慧型手機時刻」嗎？**

總結來說，RTX Spark 的推出並非為了討好所有人，尤其是那些期待「Linux-first」的開發者。它的戰略意義在於利用 Windows 龐大的用戶群，快速完成 ARM 生態系的軟體補完計畫。

這是否會成為 PC 的「智慧型手機時刻」？目前雖然言之過早，但從 Nvidia 揭露的 Roadmap 來看，這只是個開始。從現在的 Spark 到未來預計推出的 **Vera Rubin** 與 **Feynman** 架構，Nvidia 正以前所未有的速度推動計算架構的更迭。

雖然這不代表傳統 x86 架構會立即退場，但當 CUDA 的強大軟體優勢與 Windows on ARM 的硬體效率真正磨合成功時，一個高效能、具備強大在地 AI 算力的 PC 新時代就正式來臨了。我們或許該多給這項「Windows 優先」的策略一點耐心，畢竟這場由 Spark 點燃的火焰，最終照亮的不僅是 Windows 用戶，更是整個高效能運算的未來。
