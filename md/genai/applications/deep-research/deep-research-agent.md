# Deep Research Agent 技術摘要

## 1. 概述

Deep Research Agent 是一個以「搜尋優先（search-first）」為核心的研究型代理系統，使用 LangChain Deep Agents 建置。它的目標不是單純回傳搜尋結果，而是讓代理人自行規劃研究流程、拆解問題、蒐集網路來源、分析證據並產生附有引用的研究報告。

此架構特別強調研究結果的可追溯性：最終答案中的每項主張，都應該能對應至研究過程中取得的來源；完整報告則會以可下載的 Markdown 產物保存。

## 2. 核心架構

系統由兩個職責清楚分離的部分組成：

### 2.1 搜尋與 grounding 層

專案使用 Liner 作為搜尋與 grounding layer。Liner 回傳原始且結構化的搜尋結果，包括：

- 標題（title）
- 網址（URL）
- 描述（description）
- 日期（date）

搜尋層的主要責任是找出與研究問題相關的資訊與來源，而不是直接替代理解、推理或撰寫最終答案。

### 2.2 研究代理層

LangChain Deep Agents 負責後續的研究控制與內容處理，包括：

- 即時規劃研究工作
- 將大型問題拆分為較小的研究步驟
- 呼叫搜尋工具
- 收集並整理來源
- 比較與連結不同來源中的證據
- 綜合研究結果
- 為主張建立引用
- 將結果保存為 Markdown 報告

這種分層設計讓搜尋 API 專注於資訊檢索，代理則掌握推理、證據取捨與報告生成。

## 3. 研究工作流程

整體流程可概括為：

```text
Research → Plan → Search → Collect sources → Synthesize → Cite → Save report
研究      → 規劃 → 搜尋   → 蒐集來源      → 綜合       → 引用 → 保存報告
```

各階段說明如下：

1. **Research（研究）**：接收研究需求，確立需要回答的問題。
2. **Plan（規劃）**：代理根據問題建立研究計畫，並把工作拆成可執行的子步驟。
3. **Search（搜尋）**：透過 Liner 搜尋網路上的相關資料。
4. **Collect sources（蒐集來源）**：保存搜尋結果及其標題、網址、描述與日期等結構化資訊。
5. **Synthesize（綜合）**：代理分析、比較並串連不同來源的證據，形成一致的研究結論。
6. **Cite（引用）**：將最終答案中的主張與取用的來源建立對應關係。
7. **Save report（保存報告）**：把完成的研究結果輸出為可下載的 Markdown 檔案。

## 4. 設計原則

### 4.1 搜尋與推理分離

搜尋系統不負責生成最終答案，代理也不應只把搜尋結果原樣轉交給使用者。兩者分離可使：

- 搜尋層專注於召回相關資訊。
- 代理層專注於判斷資訊的重要性與可信度。
- 代理能比較多個來源，而不是依賴單一搜尋摘要。
- 最終輸出的組織方式與引用方式由研究代理控制。

### 4.2 以來源為基礎的回答

每一項最終主張都應由取得的來源支持。這種 source-backed research 方式可降低無依據陳述的風險，並讓讀者能回頭檢查證據。

### 4.3 動態研究規劃

代理不是執行固定的單一路徑，而是在研究過程中即時制定與調整計畫。透過問題拆解，複雜研究任務可轉換成多個較小且容易驗證的搜尋與分析工作。

### 4.4 研究過程可觀測

Deep Agents UI 可用來檢視整個執行過程，包括：

- 研究計畫
- 搜尋呼叫
- 取得的來源
- 最終綜合結果

因此，系統不只輸出答案，也提供研究軌跡，方便除錯、審查與理解代理的決策過程。

## 5. 技術元件與責任分工

| 元件 | 主要責任 |
| --- | --- |
| LangChain Deep Agents | 代理編排、研究規劃、問題拆解、推理與報告生成 |
| Liner | 網路搜尋、grounding、回傳結構化搜尋結果 |
| Deep Agents UI | 顯示研究計畫、工具呼叫、來源與最終綜合過程 |
| Markdown artifact | 保存並提供可下載的完整研究報告 |

## 6. 架構優點

此架構具備幾項明顯優勢：

- **可驗證性**：答案中的主張與來源建立連結，讀者可以檢查依據。
- **模組化**：搜尋服務與代理推理互相分離，方便替換搜尋供應商或調整代理邏輯。
- **彈性**：代理可根據問題動態規劃研究步驟，而非受限於固定查詢流程。
- **可觀測性**：UI 顯示完整執行軌跡，有助於除錯與研究品質審查。
- **可攜性**：以 Markdown 保存報告，格式簡單、容易下載、閱讀與後續加工。

## 7. 可能的工程考量

根據此設計，實作時應特別注意以下事項：

1. **來源品質**：搜尋結果的相關性與可靠性會直接影響研究結論。
2. **引用對齊**：引用不只是列出 URL，還需要確保每個主張確實由相應來源支持。
3. **來源去重**：多個搜尋結果可能指向相同內容，蒐集階段應避免重複計算或重複引用。
4. **研究範圍控制**：動態拆解與多輪搜尋可能增加延遲、API 呼叫次數與成本。
5. **可重現性**：應保存研究計畫、查詢、來源與產出版本，以便重跑或稽核。
6. **失敗處理**：搜尋失敗、來源不可用或證據不足時，代理應明確標示不確定性，而不是補寫沒有來源支持的結論。

上述工程考量是此類系統在落地時自然需要補足的設計面向；原始文章主要描述整體架構與工作流程，未提供具體實作程式碼或評測數據。

## 8. 總結

這個 Deep Research Agent 的核心價值，在於把網路搜尋、代理推理與來源引用組合成一條可觀測的研究管線。Liner 負責取得原始且結構化的資料，LangChain Deep Agents 則負責規劃、分析、綜合與產生報告。透過「搜尋負責找資料、代理負責決定資料意義」的職責分離，系統可以生成較具依據、可追溯且容易審查的研究結果。

其主要抽象可簡化為：

```text
結構化搜尋結果
        ↓
代理規劃與問題拆解
        ↓
多來源蒐集與證據比較
        ↓
附引用的研究綜合
        ↓
Markdown 報告與可觀測執行紀錄
```
